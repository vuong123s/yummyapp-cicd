I. Tổng quan mục tiêu và kiến trúc hệ thống

Bài thực hành nhằm trang bị kỹ năng thiết kế và tự động hóa kiểm thử phần mềm ở cấp độ chuyên nghiệp: áp dụng kỹ thuật Mocking/Stubbing để cô lập dịch vụ ngoại vi phần cứng (GPS) và trạng thái mạng viễn thông của thiết bị di động; đồng thời thiết lập đường ống tích hợp liên tục CI Pipeline với GitHub Actions trên máy chủ ảo Ubuntu, áp đặt Cổng chất lượng (Quality Gate) với ngưỡng Coverage ≥ 80% và phản xạ Fail-Fast thông qua Linter (flake8).

II. Kết quả thực thi qua 4 tiết thực hành

1. Tiết 1: Khởi tạo mã nguồn và kiểm thử cơ bản (Mức Coverage ban đầu ~35-53%)

Đã thiết lập dự án, tạo file requirements.txt ghim chuẩn phiên bản, cài đặt thư viện và chạy bộ test ban đầu chỉ chứa TestEasyLevel. Độ bao phủ của file nghiệp vụ yummy_app.py chỉ đạt 53% (thiếu toàn bộ hàm khuyến mãi và GPS), tổng hệ thống đạt 70%. Kết quả được lưu vào logs/local_test.log và thực hiện Commit đầu tiên.

2. Tiết 2: Xây dựng đường ống CI cơ bản (.github/workflows/yummyapp-ci.yml)

Đã cấu hình workflow gồm trigger trên sự kiện push/pull_request vào nhánh main, chạy trên runner ubuntu-latest với 4 bước cơ bản: Checkout code, Setup Python 3.11, Install Dependencies và Execute Test Suite.

3. Tiết 3: Kích hoạt Quality Gate và Lập trình Mocking (Vượt ngưỡng 80%)

  • Quan sát Build Báo Đỏ (Failure): Bổ sung linter flake8 và cờ coverage report --fail-under=80 vào file YAML. Do bộ test ban đầu không đạt 80% (chỉ đạt 70%), tiến trình trả về Exit Code 1, GitHub Actions bị khóa đỏ thành công đúng như thiết kế bài học.
  • Lập trình hoàn chỉnh 2 lớp kiểm thử Mocking: Bổ sung TestMediumLevel (4 kịch bản cho apply_promo_code) và TestHardLevel (3 kịch bản đóng thế GPS bằng unittest.mock.patch).
  • Kết quả sau bổ sung: Tổng số test case đạt 13/13 Pass, độ bao phủ mã nguồn yummy_app.py đạt 100%, tổng hệ thống đạt 99% (vượt xa ngưỡng 80%). Đường ống CI chuyển sang trạng thái Tích Xanh (Pass).

4. Tiết 4: Thực hành Break the Build, xuất Artifacts và Log minh chứng

  • Thực hành Break the Build có chủ đích: Cố ý tạo một hàm sai cú pháp trong yummy_app.py. Khi Linter (flake8) quét tĩnh, nó lập tức bắt được lỗi cú pháp (SyntaxError) và dừng build ngay tại bước 4 trước khi chạy test (áp dụng triệt để nguyên lý Fail-Fast). Sau đó xóa lỗi và phục hồi trạng thái build Xanh.
  • Cấu hình xuất HTML Artifacts: Thêm bước 6 trong file YAML sử dụng action actions/upload-artifact@v4 để nén và lưu trữ thư mục báo cáo coverage_html/ trong 7 ngày trên GitHub Actions.
  • Trích xuất đủ 3 file log minh chứng: local_test.log, git_history.log (có họ tên và MSSV) và github_actions_run.log.
